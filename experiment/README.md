This directory contains the experiment outputs generated by `hockey_analysis.ipynb`.

### `ur_result/`
Stores the **Uniqueness Ratio (UR) / Completeness Ratio (CR)** computation results for each table in the Hockey database.

Each table is saved as: `{table_name}_result.csv`


### `near_key_all.csv`
A summary file containing all extracted **near-keys** from the Hockey database.

- Each row corresponds to one key candidate from a table
- Includes:
  - `table_name`
  - `key` (column combination)
  - `UR(max)`
  - `CR`

This file is used as the input for later steps such as specialisation analysis and counter-example analysis.


### `specialisation_result/`
Stores the generated **specialisation lattice graphs** for selected keys (typically those with `UR(max) = 1.0`).


### `specialisation_time_result/`
Stores the runtime comparison figures for different specialisation strategies (e.g., **Normal / BFS / DFS**).


### `counter_example_result/`
Stores the outputs of **data duplication visualisation** and **counter-example analysis**.

For each near-key, this part checks duplicated groups in the database and reports:
- the **degree of violation** (how many duplicates occur)
- the **duplicate instances (counter-examples)** for manual inspection

This is mainly used to identify potential dirty data or violations of key constraints.


### `hockey_analysis.ipynb`
The main Jupyter Notebook that runs the full experimental pipeline, including:
1. Computing UR/CR for all column combinations (`ur_result/`)
2. Extracting near-keys (`near_key_all.csv`)
3. Specialisation analysis (`specialisation_result/`, `specialisation_time_result/`)
4. Counter-example analysis (`counter_example_result/`)
